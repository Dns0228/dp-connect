# План улучшений DP Connect

## Уже сделано

- Единый бренд DP Connect / DP project и палитра Graphite Mint.
- Пользовательское название протокола DP WG.
- Self-host выбран основным сценарием первого запуска.
- Убраны активные ссылки на магазин, хостинг, поддержку и новости исходного проекта.
- Обновления клиента отключены до появления собственного канала релизов.
- DP WG собирается из закреплённого исходного кода в публичный GHCR для amd64 и arm64.
- В сборке DP WG закреплена точная версия инструментов и выполняется smoke test опубликованного образа.
- Для каждого нового устройства создаётся отдельный 256-битный preshared key. Ключ одного профиля больше не используется другими устройствами.
- Перед выбором протокола добавлена проверка VPS: ОС, архитектура, память, диск, пакетный менеджер, административный доступ и Docker.
- Установка перенесена в фоновую задачу: интерфейс больше не зависает во время SSH и Docker операций.
- Вместо условного таймера показываются реальные этапы установки, включая загрузку DP WG, настройку туннеля и создание профиля.
- После запуска выполняется обязательная проверка, что контейнер находится в состоянии `running`; для DP WG и WireGuard дополнительно проверяется созданный туннельный интерфейс и его публичный ключ.
- Экран пользователей показывает имя устройства, дату создания, публичный ключ, текущую активность, последний handshake, адрес и объём трафика; доступ можно отозвать.
- Статистика DP WG читается из стабильного tab-separated dump-формата и не зависит от языка VPS.
- В управлении сервером добавлен экран состояния: контейнер, время работы, версия протокола, число устройств, образ и время последней проверки.
- Резервные копии с паролями и закрытыми ключами теперь шифруются AES-256-GCM. Ключ выводится из пароля через PBKDF2-HMAC-SHA256 с 600 000 итераций; повреждённый файл или неверный пароль отклоняется.
- Восстановление старых незашифрованных резервных копий сохранено для совместимости.
- После выбора протокола занятость всех требуемых TCP/UDP-портов проверяется до установки Docker и других изменений на VPS. Проверка не требует `lsof`, `ss` или `netstat`.

## Следующий приоритет

1. **Расширить проверку после установки.** Проверить UDP-порт с внешней стороны и первый handshake после подключения клиента. Состояние контейнера и интерфейс `awg0` уже проверяются.
2. **Собственный выпуск клиента.** GitHub Actions для Windows, macOS, Linux и Android, подпись артефактов и собственный канал обновлений DP Connect.

## После стабильного релиза

- Управление несколькими VPS из одного экрана.
- Срок действия профилей и предупреждение перед окончанием доступа.
- QR-приглашение с ограниченным сроком жизни.
- Выбор профиля: «Быстрый», «Стабильный», «Максимальная маскировка».
- Диагностика маршрутов, DNS и MTU без командной строки.
- Уведомление только о важных событиях: сервер недоступен, контейнер остановлен, доступно безопасное обновление.
