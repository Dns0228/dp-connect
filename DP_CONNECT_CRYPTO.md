# Криптографический профиль DP WG

## Принятое решение

DP WG сохраняет криптографическую конструкцию WireGuard `Noise_IKpsk2`:

- X25519 для согласования ключей;
- ChaCha20-Poly1305 для шифрования и проверки целостности;
- BLAKE2s и HKDF для хеширования и вывода ключей;
- автоматическое обновление сеансовых ключей протоколом WireGuard.

Мы не вводим собственный шифр. Новый непроверенный алгоритм увеличил бы риск ошибок и лишил бы DP WG совместимости с существующей реализацией.

## Усиление DP Connect

Для каждого нового профиля устройства DP Connect теперь независимо создаёт:

1. 32-байтный закрытый ключ X25519;
2. 32-байтный preshared key (PSK).

Пара X25519 создаётся через `EVP_PKEY_keygen`, а PSK получает случайные данные через `RAND_priv_bytes`. Результаты OpenSSL проверяются, а временные буферы очищаются через `OPENSSL_cleanse`.

Раньше серверный установщик создавал один PSK, который повторно использовался всеми профилями этого сервера. Теперь компрометация одного клиентского профиля не раскрывает дополнительный симметричный ключ других новых устройств.

## Граница защиты

Отдельный PSK уменьшает область последствий при утечке профиля и добавляет независимый симметричный секрет к обмену WireGuard. Это не делает протокол формально постквантовым и не защищает устройство, если атакующий получил его закрытый ключ и PSK.

Существующие профили продолжают работать со старым PSK. Для их перевода потребуется отдельная операция перевыпуска профиля и отзыва прежнего peer.

## Защита резервных копий

Новые резервные копии DP Connect шифруются с проверкой целостности через AES-256-GCM. Для каждого файла создаются случайные 16-байтная соль и 12-байтный nonce. Ключ выводится из введённого пользователем пароля через PBKDF2-HMAC-SHA256 с 600 000 итераций.

Заголовок формата, версия и параметры шифрования проверяются до расшифрования. Неверный пароль или изменение шифротекста приводит к отказу восстановления до импорта настроек. Старые незашифрованные копии можно восстановить без пароля для миграции.
